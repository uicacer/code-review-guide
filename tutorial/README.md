# The ACER Code Review Tutorial — Zero to Expert

A hands-on path for ACER developers. It assumes **you know nothing** about code review — or even about pull requests — and takes you to confidently reviewing AI-generated, patient-data code.

Work through the levels in order. Each one is practical: you *do* something, not just read.

> **Stuck on a word?** Everything is defined in plain language in the [Glossary](../GLOSSARY.md).

---

## The path

| Level | Title | You'll be able to… | Time |
|---|---|---|---|
| **[0](level-0-mechanics.md)** | **Mechanics & vocabulary** | Understand Git, branches, diffs, and pull requests. Open a PR and leave a review. | ~2 hrs |
| **[1](level-1-feedback.md)** | **Giving & receiving feedback** | Write clear, kind, useful review comments — and take them well. | ~1 hr |
| **[2](level-2-systematic.md)** | **Systematic review & automation** | Run a full review in priority order. Set up hooks + CI so machines do the boring checks. | ~3 hrs |
| **[3](level-3-expert-and-ai.md)** | **Expert: AI code & adversarial review** | Review AI-generated code, do a security/PHI attacker pass, and mentor others. | ~3 hrs |

By the end you can carry out every layer of the [ACER Code Review Protocol](../PROTOCOL.md).

---

## How to use this

- **If you've never used GitHub:** start at Level 0 and do the hands-on exercises for real.
- **If you already open PRs but want to review well:** skim Level 0, start at Level 1.
- **If you review but handle AI code or PHI:** jump to Levels 2–3.
- **Solo developer?** Every level has a "Solo" note — your reviewer is a mix of automation and disciplined self-review.

Nothing here is theoretical. Do the exercises on a real (or throwaway) repository and you'll learn far faster than by reading alone — *you learn review by doing review.*
